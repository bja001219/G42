## 1. 레이아웃 청사진 (세로 화면, 무스크롤)

```
┌──────────────────────────────┐  ← 우드 프레임 + 골드 라인
│ [상대 아바타·이름]  3점 1고    │  상단: 상대 정보 + 상태
│  ▩▩▩▩▩▩▩  (손패 부채, 뒷면)  │
│  상대 먹은패(작게, 분류별 줄)   │
├──────────────────────────────┤
│                              │
│        ◌ 바닥(마당) ◌         │  중앙: 초록 펠트
│     같은 달 군집·겹침          │   - 더미는 정중앙
│        🂠 더미 ×N             │   - 바닥패는 더미 주변 원형 배치
│                              │
├──────────────────────────────┤
│  내 먹은패(분류별 겹친 줄) 7점  │  하단: 내 정보
│   광[..] 띠[..] 열[..] 피[..] │
│   ╱🎴🎴🎴🎴🎴🎴🎴╲           │  내 손패 부채꼴(앞면), ✧ 표시
│        [고]   [스톱]          │  필요 시 액션 버튼/패널
└──────────────────────────────┘
```

- **세로 비율 가이드**: 상대영역 ~22% / 바닥(중앙) ~46% / 내 영역 ~32%.
  작은 화면 대응은 `LayoutBuilder`로 카드 크기를 비율 계산(스크롤 금지).
- 카드 비율 5:8 유지(`GoStopCardWidget.aspect`).
- 화투 카드 앞면은 기존 `assets/hwatu/*` PNG 재사용(자체 에셋). 보너스패(48~50)는 기존 코드드로우.

## 2. 바닥(마당) 배치 규칙

- **더미(stock)**: 화면 중앙에 뒷면 1장 + 남은 장수 배지.
- **바닥패(floor)**: 더미를 중심으로 **원형(타원) 둘레에 슬롯 분배**. 같은 달 패는
  같은 위치에 **부채/겹침**으로 한 무더기. 자리는 유동적이되, 같은 달은 항상 한 군데.
- 한 화면에 들어오도록 슬롯 좌표를 각도 기반으로 계산(예: 달별로 둘레 위치 매핑 →
  실제 화투판처럼 흩뿌려진 느낌). 넘칠 땐 반경/카드 크기 자동 축소.
- 짝 매칭이 자연스럽게 보이도록, 손패/뒤집힌 패가 날아갈 **타깃 무더기 위치**를
  레이아웃에서 정확히 알 수 있어야 함(애니메이션 도착점).

## 3. 턴 진행 애니메이션 안무 (핵심)

내 차례(원탭) 또는 상대 차례(상태 diff 재생) 공통 시퀀스:

1. **손패 한 장 나감**: 선택한(또는 상대가 낸) 카드가 손패 위치 → 바닥의 해당 달
   무더기 위치로 슬라이드.
2. **짝 매칭 하이라이트**: 같은 달 바닥 무더기가 글로우(골드 테두리) → 손패가
   **찰싹 붙음**(스케일 살짝 튕김). 짝 없으면 빈 슬롯에 **툭 안착**.
3. **먹기**: 매칭 시 먹은 패가 해당 플레이어 먹은패 영역으로 **쓸어담기** 슬라이드.
4. **더미 뒤집기**: 더미 맨 위 1장이 **중앙으로 나와 확대 + Y축 플립(뒤집기)** 후
   잠깐 정지(서스펜스 텀).
5. **붙음 vs 낙하 (불만 핵심)**:
   - 짝 O → 뒤집힌 카드가 그 달 무더기로 **날아가 찰싹**(글로우+튕김) → 먹기.
   - 짝 X → 빈 바닥 슬롯에 **툭 떨어짐**(붙는 모션 없음, 살짝 먼지/그림자).
6. **특수 이벤트 분기**: 뻑/쪽/따닥/쓸기/폭탄/총통 → 4장 콜아웃(§4).
7. **고/스톱 분기**: 7점 이상 등 조건 시 고/스톱 패널(§4).

- **타이밍(권장 초안, 리서치로 보정)**: 슬라이드 ~250ms, 매칭 글로우 ~150ms,
  먹기 ~250ms, 더미 플립 ~300ms + **정지 ~400ms(서스펜스)**, 붙음/낙하 ~250ms.
  단계 사이 짧은 텀으로 눈이 따라가게.
- **속도 옵션**: 추후 보통/빠름 토글 추가 여지(상수 1곳으로 관리).
- **애니메이션 큐**: 한 턴의 여러 동작(특히 폭탄/연속 먹기/상대 수 복원)을 순차
  재생하는 큐 필요. 재생 중 입력 잠금.

## 4. 특수 이벤트 & 고/스톱 연출

- **콜아웃(가운데 큰 글자 펑!)**: 뻑! / 쪽! / 따닥! / 쓸기! / 폭탄! / 흔들기! / 총통! /
  고! / 스톱! / 피박! / 광박! / 고박! — 0.8~1.2s, 스케일-인 + 페이드아웃, 색/아이콘 구분.
  (현재 1.1s 하단 스낵바 → 폐기)
- **고/스톱 패널**: 현재 점수 + (고 시 예상 가산) 표시, **[고] / [스톱] 큰 버튼**.
  단순 AlertDialog → 테이블 톤에 맞는 큰 패널로.
- **흔들기 확인**: 같은 달 3장 보유 시 흔들기 선언 확인(기존 로직 유지, UI만 격상).
- **폭탄 버튼**: 손패 같은 달 3장 + 바닥 1장 조건 시 노출(기존 로직 유지, UI 격상).

## 5. 먹은 패 & 점수 표시

- 분류별 **겹친 가로 줄**: 광 줄 / 띠 줄(홍단·청단·초단 색 구분) / 열끗 줄(고도리 표시) /
  피 줄(쌍피 강조, 총 피 수 크게). 같은 줄에서 카드 살짝씩 겹침(부채).
- 점수: 영역 우측에 총점 크게. 상대 영역은 축소판(분류별 줄, 더 작게).
- 점수 분해(광/띠/열끗/피/고/박/흔들기/폭탄)는 결과 화면에서 상세 표기(기존 로직 재사용).

## 6. Flutter 구현 권장 기법 (의존성 추가 없이)

> ※ 정확한 권장안은 리서치(workflow `wkmza4uaa`) 결과로 확정. 초안 방향:

- **단일 좌표계 `Stack`**: 테이블 전체를 하나의 Stack으로 두고, 모든 카드(손패/바닥/
  더미/먹은패)를 절대 좌표 `Positioned`로 배치 → 카드가 영역을 넘나들며 이동 가능.
- **이동**: `AnimatedPositioned`/`AnimationController + Tween`으로 출발→도착 보간.
- **플립**: `Transform`(Matrix4 rotateY) + 중간에 앞/뒷면 스위치.
- **상태 diff 애니메이션(상대 수 복원)**: room.state는 전체 스냅샷으로 들어오므로,
  **이전 state 보관 → 새 state와 비교**(어떤 손패가 빠졌나 / 바닥/먹은패 변화 / 뒤집힌
  더미 카드)하여 §3 시퀀스를 재구성·재생. 이를 위해 `gostop_logic`에 **직전 수 메타**
  (예: `lastMove: { actor, playedCard, flippedCard, capturedByPlay, capturedByFlip }`)를
  소폭 기록(상태 계약은 기존 키 유지 + 추가만). diff만으로 부족한 부분을 메타로 보완.
- **애니메이션 큐**: 간단한 Future 기반 순차 실행기(재생 중 입력 잠금) 자체 구현.
- **새 패키지 없음**: 햅틱은 `HapticFeedback`(flutter/services) 내장.

## 7. 법적 안전 체크리스트

> ※ 리서치 결과로 보강. 기본 원칙:

- ✅ 게임 **규칙**·**기능적 UI/UX 패턴/레이아웃 관례**는 따라해도 무방(보호 대상 아님).
- ✅ **자체/자유 라이선스 화투 카드 아트만** 사용(현재 `assets/hwatu` 유지·검증).
- ⛔ 특정 퍼블리셔의 **카드 일러스트/이미지·로고·효과음** 복제 금지.
- ⛔ **상표명**("뉴맞고", "신맞고" 등) 사용 금지. 본 게임은 자체 명칭(G42 고스톱).
- ⛔ 특정 앱 화면을 **픽셀 단위로 똑같이** 베끼지 않기(관례 차용 O, 복제 X).
- 비상업·개인 취미·미배포 전제 유지.
